## v2 修订（相对 v1）

1. **作废遮罩弹窗式拦截**——按客户端真实骨架改为**内嵌锁定态**（输入框位置虚线卡，历史/侧栏照常可浏览），回归 0918 原则「登录是增强不是门槛、任何状态不锁死进产品的路」。
2. **新增左下角账号 chip + 弹卡**（②b）：客户端当前左下角只有「训练历史/系统设置」，账号入口按 0918 映射新增，三态（未登录/已登录未订阅/会员）。
3. **改连续包月（Stripe 订阅 recurring）**：③购买页 CTA/文案、新增⑪订阅管理（自助取消=周期末止）、⑩扣款提醒与失败 dunning、④回跳含下期扣款日。
4. **退款政策落地**（点点定方向：已使用按剩余额度比例退）：
   - 未使用（0 token 消耗）且 14 天内 → **全额退**
   - 已使用 → **退款 = 实付 ×（剩余额度 ÷ 本期初始额度）**，Stripe Refund 部分退款
   - 流程：邮件申请（自动附账号/订阅/用量摘要）→ 人工审核 1~3 工作日 → Dashboard 部分退款 → 订阅立即取消+剩余额度清零
   - MVP 不建自助退款，⑪管理页放「申请退款」mailto 入口
5. 邮件两枚（到期扣款提醒/扣款失败）列入 P3。

## 订阅状态机（工程侧约定）

- Stripe Checkout（subscription mode）→ `invoice.paid` webhook → accounts 发放本期额度（基础 625 万 / 高频 1875 万 quota）→ 绑定用户 new-api 令牌。
- 取消 = cancel at period_end：当前周期额度仍可用，周期末自动止。
- 扣款失败 = Stripe Smart Retries 自动重试（~7 天窗口），期间不锁定；彻底失败进⑫。
- 升级档位：默认**次周期生效**（简单、无补差计算）；如需立即升级按剩余比例折算补差（待定点 2）。

## 待点点拍板的待定项

1. **档位名**：暂「基础档/高频档」。
2. **升级生效**：次周期（线稿默认）vs 立即补差。
3. **加速包**（⑨的一次性加购）：确认要做；定价 ¥10/120 轮同基础档。
4. **退款审核**：客服邮箱用哪个地址；是否设「已使用超过 50% 不予部分退」等下限条款。
5. 邮件模板（P3）：发件人名/署名。
