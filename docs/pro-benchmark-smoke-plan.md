# 高手基准 CV 冒烟验证方案（点点回家在 Windows 实跑）

> **状态：待执行。** 2026-08-27 与点点对齐后落库的验证方案。目的：在立项"高手基准离线提取工具"之前，用真实高手录像量化现有免校准 CV 管线的精度边界。本文档不是产品合同。

## 一、背景与两条线（点点 2026-08-27 拍板）

1. **内化路线（本方案服务它）**：我们离线用高手录像做高精度分析（慢速多 pass＋人工校验），把"顶尖高手按场景×指标的基准数值"内化进 `knowledge/` 体系，Coach 讲评时引用（补上"方向性知识有、数值锚没有"的缺口）；
2. **运行时对比（保留探索）**：客户端"对比你和高手"作为**标注实验性**的功能继续想办法，精度不足时可降级为仅轨迹/结构指标。本冒烟的数据同时为它标定现实基线。

## 二、样本收集清单（5 个，维度尽量散）

| # | 维度 | 要求 |
|---|------|------|
| 1 | 场景类型 | clicking 类（如 1w6ts）×2、tracking 类 ×1、target switching 类 ×1、任选 ×1 |
| 2 | 来源 | YouTube ≥2、B 站 ≥2（不同 UP） |
| 3 | 画质 | ≥1080p60 ×2、720p30 ×1（测压缩鲁棒性） |
| 4 | 画面干扰 | 带 overlay/水印/摄像头画中画 ≥1、干净画面 ≥3 |

下载尽量取原画（video-only 最高码率即可）。每个视频记录：场景名、高手名、来源 URL、时长。

## 三、跑法

环境：能跑本仓库 Python 侧的环境（需要 opencv-python、numpy，客户端开发环境已具备）。仓库根目录执行：

```
python scripts/pro_smoke.py <视频路径> [--sample-every 10] [--max-frames 3000]
```

建议两轮：第一轮 `--sample-every 10` 快速摸底（约几十秒/视频）；有希望的再全帧跑（数分钟可接受）。脚本只读视频、只打统计，不写仓库文件。输出 JSON 直接复制回填下表。

## 四、要记录的数字（脚本输出字段）

| 字段 | 含义 | 关注什么 |
|------|------|----------|
| `fail_closed` | 颜色假设选择是否失败 | 若 true＝该视频免校准管线直接放弃，记画面特征 |
| `frame_coverage_pct` | 检出≥1 目标的帧占比 | **主指标**：clicking 场景应 ≥90% |
| `targets_per_frame` | 每帧目标数 min/p50/p90/max | 与场景应有目标数比对（1w6ts 应 1–6 浮动）；max 异常大＝把 HUD/背景误当目标 |
| `shape_distribution` | 球/胶囊/人形分布 | 与场景目标形状常识比对 |
| `zero_detection_runs` | 连续 0 检出段的条数与最长长度 | 长段（>1 秒帧数）＝可疑漏检区，回看视频确认 |
| `wall_seconds` | 总耗时 | 为慢速多 pass 模式定时间预算基线 |

人工对照（脚本之外）：视频里可见的计分板击杀数，与"目标数下降事件"肉眼比对的误差，记个大概。

## 五、判读标准（跑完回来定夺）

- **立项离线提取工具**：clicking 样本 coverage ≥90% 且计数合理、fail-closed ≤1/5；
- **记录失败模式再评估**：coverage 70–90% 或干扰样本全挂——失败模式集中在哪（颜色假设/形状判定/overlay 遮挡）决定工具要补哪块；
- **仅 tracking 可用**：clicking 不行但 tracking 轨迹可用——先内化 tracking 类基准，clicking 类另想办法。

## 七、已知边界

- `scripts/pro_smoke.py` 写于 2026-08-27，**未经实跑验证**（仓库机器无样本视频）；调的是当时 `generic_visual_detection` 的公开函数（`select_color_hypothesis` / `detect_generic_targets`），接口若已变动，报错原样带回仓库修；
