# 外设推荐能力显化与访谈输入

> 状态：2026-08-01 assessment / interview input。本文用于把当前项目实际能看到的信号整理成逐轮访谈的起点，不是 PRD、Architecture、active spec 或 implementation plan，也不授权直接实现商品目录或推荐接口。

## 1. 目的

最终目标是让 Coach 在证据和用户上下文足够时，给出多个有解释的具体外设型号，并在用户明确请求后打开购买链接。

当前先不问型号。第一步是把点点已经掌握的外设判断知识提取成可复用的知识卡：

```text
瞄准诊断与训练建议 -> 用户明确外设意图 -> 可能的外设特征需求 -> 用户确认问题 -> 低成本验证 -> 快照规格筛选 -> 已核验型号 -> 购买链接
```

其中“可能的外设特征需求”不是因果诊断。只有用户报告、单变量实验和可比复测共同支持时，Coach 才能提高该候选的可信度。

## 2. 当前项目实际可见的事实

### 2.1 确定性输入与指标

- Windows Raw Input 只在 KovaaK 进程 gate 内记录相对 `dx/dy`、时间戳和鼠标按钮；它描述输入运动学，不描述鼠标型号、重量、形状、摩擦或握法。
- Stats / Performance 提供场景、挑战时间窗、击杀/命中事件和可用配置；MP4 主要提供视觉回放、问题定位和视觉证据。
- 当前分析可以暴露速度、修正次数、settle time、`reverse_ratio`、SPARC、tracking error 等运动表现。它们是“动作发生了什么”的证据，不是“哪件硬件造成了它”的证据。
- 本地校准档案实际保存 `cm_per_360` 和 `fov`。`dpi` 与 `sensitivity` 目前只是输出兼容字段，未形成可用的持久化设备设置事实。

### 2.2 用户必须补充的事实

当前系统无法从 Raw Input 或轨迹可靠得到以下信息，只能由用户报告或后续实验提供：

- 当前鼠标、鼠标垫、脚贴和设置；
- 手长/手宽、实际握法、手指和手腕的空间是否受限；
- 用户觉得“哪里不顺手”、是否有摩擦或控制感变化；
- 疲劳、疼痛、麻木、无力等安全相关反馈；
- 预算、地区、重量偏好、无线/有线取舍和购买渠道。

### 2.3 可用的验证方式

- 保持场景、灵敏度和其他条件不变，只改变一个外设特征或设置；
- 先做即时同条件复测，再做延迟同条件复测；
- 把近迁移和主游戏迁移单独记录，不能把训练器分数提升直接当成购买有效；
- 用户报告不适时先停止相关实验，不把它自动解释为某个硬件或身体原因。

## 3. 当前外设知识的实际边界

Knowledge Registry v4 已经有外设相关的来源和边界，但它们不是商品目录：

| 知识条目 | 当前允许的用途 | 明确不能做什么 |
|---|---|---|
| `community.friction-and-surface` | 解释摩擦、鼠标垫/脚贴差异；用户主动提出后做单变量实验 | 不能从 Raw Input 推断垫子或脚贴问题；不能把购买当训练前提；没有摩擦系数测量 |
| `community.task-specific-sensitivity` | 解释任务相关的灵敏度取舍；做用户选择的设置实验 | 不能声称存在一套完美灵敏度；不能从 `cm/360` 推断肌肉使用 |
| `community.adaptive-mouse-grip` | 解释握法和舒适度话题 | 只能解释，不能从轨迹推断握法、姿态、施力或医疗状态 |
| `community.mouse-acceleration-context` | 解释加速映射；在用户确认后做可逆设置实验 | 不能自动修改设置，也没有读取并验证实际加速曲线 |
| `hypothesis.tension-management` | 只有用户报告后，围绕一个 cue 做实验并匹配复测 | 不能说系统“检测到了张力”或诊断肌肉、关节、握法和疼痛原因 |

## 4. 现有 Coach 行为能走到哪里

- 用户主动问“要不要换鼠标/外设”时，Coach 可以先问用户想解决的具体问题。
- 没有可重复观察或用户上下文时，当前安全回答是“不足以支持换鼠标”，不会主动塞入商品建议。
- 有用户报告和合适的 Registry 条目时，可以解释一个可能的特征并建议可逆验证。
- 现有 `TeachingSession`、确认、执行记录和复测记录可以承载训练实验的事实边界；现有正式 Training Plan 编译链主要绑定已审核的场景处方，尚没有外设商品或外设实验专用的事实合同。
- 当前业务代码仍没有商品候选排序器、地区价格/库存事实、联盟字段或购买链接 UI；但仓库已有一次性鼠标规格快照和一组严格核验的 JD 身份映射，可作为后续知识合同的商品事实输入。

### 4.1 不应主动触发外设推荐的情况

仅凭以下分析现象，不应主动把鼠标、鼠标垫或脚贴列为解决方案：

- 打到目标后需要多次修正；
- 落点变慢、修正次数偏多或轨迹不够平滑；
- `reverse_ratio`、`corrective_count`、settle time 或 SPARC 持续较差；
- 用户没有主动报告设备问题、舒适度问题或设置变化。

这些现象默认属于瞄准手部控制、动作策略或训练问题。它们最多帮助 Coach 选择训练观察和复测，不构成硬件限制证据。

### 4.2 鼠标商品事实层与使用边界

已接入知识合同的鼠标商品事实有两层，均为本地、一次性快照，不是实时库存或自动更新源：

- `artifacts/eloshapes/snapshots/eloshapes_mouse_catalog_2026-07-31T211736Z.json`：2026-07-31 抓取的 1,617 条唯一鼠标记录、65 个字段。可核对品牌、型号、变体、三围、重量、形状、驼峰、前端 flare、侧曲率、左右手兼容、连接方式、传感器、开关和编码器等静态规格；每次使用都要保留快照日期和来源。
- `artifacts/eloshapes/marketplace-mapping/marketplace-mapping.json`：171 条 JD `identity_verified_candidate`。每条同时核对 EloShapes ID、品牌、型号、变体、数字 SKU、规范商品 URL、商品标题、证据 URL 与核验时间，才可进入购买候选。它不证明此刻有货，也不是联盟链接。

| 层级 | 可以使用的字段/状态 | Coach 可以说或做什么 | 必须留在层内、不能当作 Coach 推荐事实的内容 |
|---|---|---|---|
| Coach 对话与建议 | 用户报告的当前设备和体验；经精确匹配后的快照规格，如品牌/型号/变体、三围、重量、形状、驼峰、侧曲率、握持兼容和连接方式；同条件复测结果 | 用普通语言说明相对特征，例如“你想要更轻一点的选择”；对比当前设备与候选的静态规格；说明这只是待验证的选择，不把它说成问题成因 | EloShapes ID/handle、搜索别名、SKU、规范 URL、证据 URL、店铺、核验时间、库存或价格断言；未核对当前型号时不能假定它的规格 |
| 检索与匹配 | EloShapes ID/handle；品牌、型号、变体；`catalog-aliases.json` 中的中文名、缩写、社区称呼；全目录的 pending/research 状态和快照来源 | 将用户报出的设备名称规范到一个精确快照记录，再按已确认的特征筛选候选 | 别名和搜索结果只帮助检索，不能证明商品身份；`jd_unresolved`、`taobao_not_verified` 只能表示审查证据不足，不能说成“不卖”或“找不到” |
| 运营与购买 | 映射中的 `identity_verified_candidate`、JD `product_id`、`canonical_url`、`listing_title`、`seller/store`、`availability`、`match_confidence`、`evidence_url`、`checked_at`、`reason`；后续联盟转换结果 | 在产品后端重新转换并确认可点击后，向已选型号提供购买入口 | 原始 `canonical_url` 不能直接作为推广链接；历史 `availability` 不能当作实时库存；淘宝 `item_id=0` 必须保持 `not_verified`，绝不能猜测或补造 |

当前这一批数据只覆盖鼠标。鼠标垫的滑度、脚贴与摩擦力还没有同等的、可用于型号筛选和购买身份核验的事实层；即使用户确认“想更滑/更涩”，目前也只能讨论特征和单变量实验，不能据此给出鼠标垫或脚贴型号、库存或链接。

### 4.3 从表现到购买入口的准入顺序

1. **先完成瞄准诊断。** Coach 默认给训练或复测建议，不主动推销外设。只有用户主动问外设，或在诊断结束后明确同意继续，才进入这条路径。
2. **把表现写成候选方向，而不是硬件结论。** 例如已确认的“启动慢且刹车慢”可以提出“可能想试更轻的鼠标”；还必须保留训练、设置、疲劳等竞争解释。没有用户报告的设备问题时，像多次修正、落点变慢等现象仍停在训练分析。
3. **收集能改变判断的事实并做复测。** 先问当前鼠标和鼠标垫，以及用户觉得哪里不顺手；随后按需要确认主观感受、手长、握法和支撑感。保持场景、灵敏度和其他条件不变，一次只改一个变量，确认这个特征方向值得继续。
4. **按相对特征筛选快照。** 当前型号被精确匹配后，才能用其重量、尺寸和形状作为基线；候选先满足已确认的体验/特征，再比对快照规格。当前型号无法精确匹配时，不虚构基线，只继续澄清或停在特征建议。
5. **型号和购买入口分别过闸。** 只有候选同时存在于鼠标快照、且有品牌/型号/变体完全一致的 JD `identity_verified_candidate` 映射时，才进入具体型号候选。没有精确映射时只谈特征，不给型号或购买链接。即使映射存在，也只能由购买/联盟层把规范 URL 转成当次可用的最终链接；转换失败、商品下架或状态失效时，链接不可点击。

3D 外形暂时不进入上述闸门：目前没有已验证、允许再分发的 GLB artifact。它可以是未来的形状查看能力，不能成为当前型号比较或购买推荐的依赖。

## 5. 访谈知识卡格式

每次只处理一个外设问题，点点的回答先记录为访谈来源，不直接升级为普遍规则。每张卡包含：

1. **用户会怎么说**：不用指标名和专业术语；
2. **需要追问的最少事实**：只问能改变判断的问题；
3. **可能涉及的外设特征**：例如尺寸、形状、重量、平衡、表面、脚贴或设置；
4. **竞争解释**：同一表现也可能来自训练、灵敏度、视觉条件或疲劳；
5. **先做的低成本验证**：一次只改一个变量；
6. **什么结果才允许进入型号筛选**；
7. **不适合的型号特征、例外和反例**；
8. **证据等级和适用范围**：个人经验、社区实践、实验结果或产品事实。

### 5.1 访谈卡：用户主动提出更换鼠标

> 来源：点点外设推荐访谈，2026-08-01。当前是用户经验规则，不是已验证的普遍产品规则。

触发条件：用户主动说想换鼠标，但没有提供其它背景。

第一轮只收集两件事：

1. 当前使用的鼠标和鼠标垫；
2. 用户觉得当前鼠标主要有什么问题。

推荐的自然问法是：

> 你现在用的鼠标和鼠标垫是什么？你觉得当前鼠标主要有什么问题？

在这两个事实拿到之前，不进入尺寸、重量、握法、表面或具体型号推荐。

### 5.2 访谈卡：持续追踪表现与外设候选

> 来源：点点外设推荐访谈，2026-08-04。当前是用户经验规则，不是已验证的普遍产品规则。

持续追踪可以细分描述为：持续落后或超前、变向后才跟上、速度持续不匹配、偏离次数/时长/重新跟回耗时偏多、来回修正，以及轨迹不够平滑。

用户可能会说：“鼠标移动时感觉有点卡卡的、顿顿的。”

- 持续落后/超前、变向跟随、速度匹配、偏离与重新跟回、来回修正：默认仍是瞄准控制、动作策略、训练或设置话题，不因为这些表现把外设列为候选。
- 轨迹持续不够平滑：可以在用户主动同意讨论外设、且已拿到当前鼠标垫信息后，保留“试试稍快一点的鼠标垫”这一候选方向。

这不是从平滑度字段直接断言“鼠标垫太涩”。在补齐用户对当前表面的主观感受和同条件单变量复测前，Coach 只能把它说成一个可尝试的方向；鼠标垫商品事实层尚未建立，因此当前不能给出具体型号或链接。

## 6. 访谈规则

- 一次只问一个问题，下一题根据上一题回答生成；
- 先用普通用户语言描述情境，再在必要时给出指标解释；
- 不把“表现差”改写成“硬件导致”；
- 不要求用户先理解 `reverse_ratio`、SPARC 等内部名称；
- 多种可能可以保留为多个候选，但每个候选必须有对应的追问和验证方式；
- 具体型号和链接放在特征规则稳定之后：型号还需对应快照与精确身份映射，购买链接还需由购买/联盟层当次转换；任一条件不满足时，停在特征与实验层。
